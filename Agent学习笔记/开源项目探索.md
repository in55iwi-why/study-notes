# 开源项目探索

---

## 1. Scrapling：把「抓一个页面」到「爬整个站」做成一个库

- 仓库链接：https://github.com/D4Vinci/Scrapling
- 官方文档：https://scrapling.readthedocs.io/en/latest/

### 它能解决什么问题

我们做前端项目时经常需要外部数据，但手搓会遇到一堆麻烦：网站有反爬、页面是 JS 渲染的、爬一半被限流、中途中断得从头再来、抓下来的数据格式乱。Scrapling 能很好的解决这些问题。

### 我觉得值得借鉴的地方

1. **分层抽象，上层接口统一。** 它把取数方式分为Fetcher`、`StealthyFetcher、Spider三层，但拿到的 `Response` 对象和 CSS/XPath 选择器是同一套。借鉴：数据层应该让取数方式可替换，而上层拿到的数据结构保持一致，这样测试时可以用假数据替换真实请求，不用改业务代码。

2. **开发模式：第一次缓存响应，之重放。** 调解析逻辑时不用反复打真实网站。这个我觉得最实用：既快，又不会把对方网站打崩。借鉴：开发和演示时用固定数据，保证稳定。

3. **断点续爬。** 设置 `crawldir` 后按 Ctrl+C 会保存待处理请求和已访问 URL，下次用同一个目录继续。借鉴：前端界面上也应该能显示进度和恢复状态。

4. **AutoThrottle 和遵守 robots.txt。** 它根据网站响应速度自动调节延迟，被限流就降速、缓过来再提速。借鉴：调用外部接口要有退避，不能无脑重试。

5. **输出格式直接可用。** 支持 JSON / JSONL / CSV / XML，还能一行代码转 Markdown 给大模型用（`page.markdown()`），不用再自己清洗。

### 我为什么选它

贴近我们前端组的实际需求，Python 上手门槛不高，而且它的数据层设计思路可以直接写进项目计划书的数据获取方面里。

## 2. REA：把「逆向工程」包装成 MCP 给 Agent 用

- 仓库链接：https://github.com/morluto/rea
- 官网：https://rea.tools

### 它能解决什么问题

你看到某个软件里的功能想知道怎么实现的，让 Agent 调 REA 去分析这个应用，它会给出解释和证据，甚至帮你照着做一个。支持的目标包括原生二进制、JavaScript / Electron 应用、网站、.NET 程序集、Android 应用、固件，以及录制的运行和网络活动。

### 我觉得值得借鉴的地方

1. **Evidence 优先，而不是只给结论。** README 里反复强调结果包含每条结论背后的证据和限制。借鉴：我们以后做 AI 相关功能，输出不能是一个黑盒答案，得能追溯到来源，并且明确告诉用户哪些地方不可靠。

2. **一次 setup 同时接入多个 Agent。** `npx rea-agents setup` 会注册 MCP 服务并安装配套的工作流 Skill，支持 Claude、Codex、Cursor 等。借鉴：工具设计时要能够考虑到能否给agent使用。

3. **Offline-first，不依赖宿主工具。** 比如它解析 ISO 9660 镜像时直接读卷描述符和目录树，不挂载镜像、不调外部命令。借鉴：少依赖外部环境 ，更容易复现、更安全，也更容易排查问题。

4. **资源预算限制。** 它对解析深度、记录数量、路径长度、元数据体积都设了上限，防止恶意输入把程序卡死。借鉴：解析外部数据时一定要设定边界。

5. **能力校验不只看版本号。** Windows native 插件用显式的 capability 判断旧插件能不能用，避免「版本号一样但能力不够」的坑。这个细节挺老练的。

### 我为什么选它

它在GitHub以及抖音等平台都非常火爆，并且它解析功能的作用可以用到后续开发中，为项目增加功能时能解决很多问题。它的工程设计思想是通用的：可解释输出、统一错误模型、多入口一致性、资源边界。这些都能迁移到项目的计划书和代码结构里。
